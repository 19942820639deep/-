# A股定时分析免费行情快照

这个仓库只负责采集和校验公共A股行情，不产生买卖结论，也不存储任何账户、持仓或交易记录。

## 数据流程

1. 交易日北京时间10:05—10:35、11:15—11:35、14:10—14:50及15:00—15:10每五分钟运行GitHub Actions，以吸收免费定时任务的排队延迟。
2. 腾讯公共行情端点提供全A排行、指数和逐股详细报价。
3. 新浪公共行情端点独立核验流动性候选股的价格与成交时间。
4. 同花顺金融数据API提供行业/概念目录、板块指数、当前成分股及涨停/跌停/炸板池；程序再用腾讯逐股行情复核成分股宽度和容量核心。
5. 程序重新计算市场宽度、成交额、非ST涨跌停和炸板数量，同时保留同花顺特色股票池的独立口径，避免混为同一统计口径。
6. 只有时效、覆盖率、指数完整性、跨源价格以及板块宽度全部通过，`valid_for_tail_selection`才为`true`。
7. `validity_profiles`分别标记盘中实时、午间收盘、前一交易日收盘和尾盘选股是否可用，禁止跨时段混用。
8. 每次运行无论成功或失败都更新独立状态文件；采集失败时保留上一份成功快照，同时明确记录本次错误，不再静默留下旧文件。

## 定时分析的主动采集规则

GitHub Actions 的免费 `schedule` 没有准点运行 SLA，可能排队或漏触发。因此盘中分析任务不得只等待仓库中的被动快照：

1. 先读取仓库快照；满足对应时段的硬校验即可直接使用。
2. 快照过期时，在分析任务自己的运行环境中临时拉取本仓库并执行 `python collector.py`，现场生成快照。
3. 现场快照仍须通过同一套时效、覆盖率、指数和腾讯/新浪跨源校验；失败就停止具体行情判断。
4. GitHub Actions 快照同时缓存最近7日已验证板块的成分映射。现场环境没有`THS_API_KEY`时，采集器用腾讯全市场实时价格重新计算这些板块的宽度、强度和容量核心；绝不沿用缓存中的涨跌幅。
5. 缓存板块只用于验证当日已发现方向，不能宣称发现新的下午板块；新方向仍需实时同花顺数据或其他独立板块源确认。
6. 全市场排行和详细报价采用最多6路受控并发，避免串行采集超过尾盘决策窗口；重试、覆盖率和跨源校验标准不降低。

## 硬校验

- 最新逐股行情时间距采集时间不超过240秒；
- 全市场覆盖不少于5000只，详细报价覆盖率不低于95%，且不低于上一份快照股票数的95%；
- 上证、深证、创业板、科创50四个指数全部存在；
- 腾讯与新浪至少匹配30只候选股，95分位价格差不超过0.3%；
- 同花顺候选价格交叉校验作为第三来源保留；尾盘价格硬门槛以腾讯/新浪至少30只、95分位价差不超过0.3%为准；
- 同花顺强势行业/概念必须有可用板块指数，并以至少3只成分股复核；至少6个板块完成宽度校验；
- 行情校验失败时在快照中发布失败原因；采集程序异常时在`status.json`发布失败阶段、错误信息、运行编号及上一份快照时间，下游任务不得把旧快照当作实时行情。

## 同花顺 API Key 配置

1. 在同花顺金融数据服务创建API Key；不要把Key提交到仓库、聊天或截图中。
2. 打开本仓库 `Settings → Secrets and variables → Actions → New repository secret`。
3. 名称填写 `THS_API_KEY`，值填写完整API Key并保存。
4. 在 `Actions → A-share tail snapshot → Run workflow` 手动运行一次。
5. 检查 `data/status.json`：`run_status`应为`success`；再检查`data/latest.json`中的`validation.hithink_configured`、`hithink_price_cross_pass`和`sector_data_pass`均为`true`。

程序只把Key作为`X-api-key`请求头使用，不写入URL、日志、`latest.json`或`status.json`。同花顺异常时，若仓库已有最近7日验证过的板块成分映射，程序会用现场腾讯报价重新计算宽度；若没有合格映射，才停止板块选股。持仓风控只依赖已通过双源校验的实时个股与指数，不再被板块接口连带阻断。

## 免费数据边界

免费接口没有商业SLA，可能限频、断连或调整字段。本项目通过受控调用、重试、多源校验和硬性空缺机制降低风险，但不会把免费接口包装成专业授权行情。
